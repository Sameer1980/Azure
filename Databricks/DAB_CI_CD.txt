Databricks Asset Bundles are a tool to facilitate the adoption of software engineering best practices, including source control, code review, testing and continuous integration and delivery(CI/CD), for your data and AI projects.
Bundles provide a way to include metadata alongside your project's source files and make it possible to describe Databricks resources such as jobs and pipelines as source files.
Ultimately a bundle is an end-to-end definition of a project, including how the project should be structured, tested and deployed. This makes it easier to collaborate on projects during 
active development.

This databricks.yml configuration snippet defines custom deployment presets for a Databricks Asset Bundle (DAB) target, customizing how resources are named and deployed.
         name_prefix: 'dev_${workspace.current_user.short_name}':
                   --Automatically prepends a custom string to the names of all deployed resources (like jobs or pipelines).
                   --Uses the current user's short username (e.g., dev_john.doe) to prevent naming conflicts when multiple developers deploy the same bundle to a shared workspace.


  'source_linked_deployment: false':
         --Disables source-linked deployments, meaning the deployed resources use copied workspace files rather than directly pointing to active source files in your workspace folder                          during workspace-based deployments. Meaning you do not need to use the source linked path. You always need to deploy using this path , '../../src/notebooks/notebooks.ipynb' .

Q) What is the importance of this '.databricks' folder and how asset bundles track changes within this particular .bundle folder?
A) This '.databricks' folder is basically the transaction log , the version control system. The '.json' file under the 'ASSETBUNDLE->dabtutorial-> .databricks-> sync_snapshots' folder 
    is the snapshot of the last deployment.
   So if we want to deploy another notebook under 'src' folder( 'ASSETBUNDLE->dabtutorial-> src -> notebooks') named 'notebooks2.ipynb' , it will check the above '.json' file before 
   deploying it to the target. With the help of the above '.json' file it will do incremental deployment.
  For any fresh deployments with new notebooks and pipelines delete the '.databricks' folder and run C:\Users\samir\OneDrive\Desktop\databricks\ASSETBUNDLETUT\dabtutorial> 'databricks bundle deploy --target dev'. It will do a full deployment of all the things.
